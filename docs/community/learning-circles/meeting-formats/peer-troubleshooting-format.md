# Peer Troubleshooting Format

Collaborative problem-solving sessions.

## Overview
**Duration:** Ongoing (drop-in) or 6-week intensive
**Group Size:** 4-8 educators
**Best for:** Building debugging skills, solving current problems

## Structure Options

### Option A: Drop-in Troubleshooting
- Weekly standing meeting
- Open to all
- Bring current problems
- Collaborative debugging
- Build community knowledge

### Option B: Intensive Troubleshooting Course
- 6-week structured program
- Learn systematic troubleshooting
- Practice on real problems
- Build diagnostic skills

## Meeting Agenda Template (60 min)

**Opening (5 min):**
- Check-in
- Identify problems to tackle
- Prioritize based on:
  - Safety concerns (first)
  - Shared learning value
  - Time available
  - Complexity

**Problem 1 (15-20 min):**

**Present (3 min):**
- Educator describes problem
- What's happening?
- What have you tried?
- What resources consulted?

**Clarify (3 min):**
- Group asks clarifying questions
- Get full picture
- Identify relevant factors

**Troubleshoot (10 min):**
- Hypothesize causes
- Suggest diagnostics
- Walk through debugging steps
- Reference resources
- Live troubleshooting if possible

**Synthesize (2 min):**
- Action plan for presenter
- Key learning for group
- Resources to consult

**Problem 2 (15-20 min):**
- Repeat structure

**Problem 3 (15-20 min):**
- Repeat structure
- Or: Continue deep-dive on complex problem

**Closing (5 min):**
- What did we learn?
- Common patterns noticed?
- Skills we're building?
- Follow-ups needed?

## Troubleshooting Framework

**1. Define the Problem**
- Exactly what's happening?
- Expected vs. actual behavior
- When did it start?
- What changed?

**2. Gather Information**
- Error messages
- Configuration settings
- Hardware setup
- Software versions
- Environmental factors

**3. Develop Hypotheses**
- What could cause this?
- Most likely to least likely
- Check assumptions

**4. Test Systematically**
- Change one variable at a time
- Document each test
- Observe results carefully
- Follow evidence

**5. Solve and Verify**
- Implement solution
- Verify problem is solved
- Understand why it worked
- Document for future

**6. Share Learning**
- Post solution in Discussions
- Update troubleshooting guides
- Help others with same issue

## Common Problem Categories

**Hardware:**
- Motors not spinning
- Sensors not reading correctly
- Power issues
- Connections/wiring
- Component failures

**Software:**
- Configuration errors
- Firmware issues
- Programming bugs
- Communication problems
- Integration challenges

**Flight/Operation:**
- Unstable behavior
- Poor performance
- Unexpected responses
- Mission execution problems

**Pedagogical:**
- Student engagement
- Assessment challenges
- Differentiation needs
- Classroom management

## Building Troubleshooting Skills

Over time, circles should:
- Develop systematic approach
- Build pattern recognition
- Create troubleshooting resources
- Document common solutions
- Train newcomers
- Contribute to community knowledge

## Tips for Effective Troubleshooting

**For Presenters:**
- Describe clearly
- Share what you've tried
- Be open to questions
- Follow up after solving

**For Helpers:**
- Ask don't assume
- Suggest don't dictate
- Teach fishing, not giving fish
- Build presenter's skills

**For All:**
- No "stupid questions"
- All problems are valid
- Celebrate progress
- Learn from each case
- Document solutions

## Follow-Up
- Report back on solutions
- Share documentation
- Help others with similar issues
- Build community troubleshooting guide
