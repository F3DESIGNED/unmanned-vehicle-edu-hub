# How to Contribute

Thank you for your interest in contributing to the Unmanned Vehicle Systems Education Hub! Every contribution, no matter how small, helps advance our mission of accessible, high-quality unmanned vehicle systems education.

## Ways to Contribute

### 🗣️ Answer Questions (Easiest Start!)

**Time commitment**: 10-30 minutes
**Skill level**: Any

Help others in [GitHub Discussions](https://github.com/F3DESIGNED/unmanned-vehicle-edu-hub/discussions):

- Answer technical questions
- Share teaching strategies
- Offer troubleshooting advice
- Provide encouragement

**Why it matters**: Your experience helps others avoid the same struggles you faced.

**Getting started**:
1. Browse Q&A categories
2. Find questions you can answer
3. Share what worked for you
4. Be patient and supportive

### 📚 Share Lesson Plans

**Time commitment**: 2-5 hours (for complete lesson)
**Skill level**: Classroom experience helpful

Contribute your teaching materials:

- Complete lesson plans
- Activity worksheets
- Assessment rubrics
- Lab procedures
- Project ideas

**What to include**:
- Learning objectives
- Grade level and duration
- Required materials
- Step-by-step procedures
- Assessment strategies
- Differentiation suggestions
- Alignment to standards

**How to submit**:
1. Review [Lesson Plan Template](../../curriculum-integration/lesson-plans/lesson-plan-template.md)
2. Create your lesson plan
3. Submit via [Lesson Plan Exchange Discussion](https://github.com/F3DESIGNED/unmanned-vehicle-edu-hub/discussions)
4. Community provides feedback
5. Maintainers merge to repository

### 💻 Contribute Code

**Time commitment**: Varies
**Skill level**: Programming experience

Share code examples, utilities, and tools:

- Arduino/Python example code
- Automation scripts
- Data analysis tools
- Web-based simulators
- Testing utilities

**Guidelines**:
- Follow existing code style
- Include comments and documentation
- Provide usage examples
- Test thoroughly
- Add appropriate license

**How to contribute code**:
1. Fork the repository
2. Create feature branch
3. Add your code with documentation
4. Test thoroughly
5. Submit pull request
6. Respond to review feedback

See [CONTRIBUTING.md](../../../CONTRIBUTING.md) for technical details.

### 🔧 Share Hardware Designs

**Time commitment**: 3-8 hours
**Skill level**: Hardware experience

Contribute build guides, adaptations, or new designs:

- Complete build guides
- 3D printable parts
- Circuit diagrams
- Bill of materials
- Assembly instructions

**Required elements**:
- Clear documentation
- Parts list with sources
- Assembly photos/diagrams
- Testing procedures
- Safety considerations
- Estimated cost and time

**Formats accepted**:
- Markdown documentation
- STL files for 3D printing
- Fritzing or KiCAD files
- Photos and videos
- SVG/PDF diagrams

### 🎥 Create Video Content

**Time commitment**: 5-20 hours per video
**Skill level**: Video production helpful

Contribute tutorials, demonstrations, or explanations:

- Technical how-tos
- Troubleshooting guides
- Build walkthroughs
- Concept explanations
- Classroom implementations

**Requirements**:
- Clear audio and video
- Captions/subtitles (required)
- Organized structure
- Safety emphasis
- Educational focus

See [Video Production Guide](../../../media/video-content/production-guide/) for details.

### 🐛 Report Issues

**Time commitment**: 5-15 minutes
**Skill level**: Any

- Safety concerns
- Outdated information
- Accessibility issues

**How to report**:
1. Check if issue already exists
2. Open new issue in GitHub
3. Provide specific details
4. Include steps to reproduce
5. Suggest fixes if possible

## Contribution Quality Standards

### All Contributions Should:

✅ **Be educational** - Focus on teaching and learning
✅ **Be safe** - Emphasize safety-first approach
✅ **Be tested** - Verify it works before sharing
✅ **Be clear** - Write for your audience's level
✅ **Be complete** - Include necessary context and details
✅ **Be original** - Your work or properly attributed
✅ **Be accessible** - Consider diverse learners

### Avoid:

❌ **Untested content** - Don't share "I think this works..."
❌ **Unsafe practices** - Never compromise on safety
❌ **Plagiarism** - Always give credit
❌ **Commercial promotion** - Focus on education, not sales
❌ **Incomplete resources** - Provide enough to be useful
❌ **Overly complex** - Match the target audience

## Contribution Workflow

### For Documentation/Resources:

1. **Explore** - Review existing resources
2. **Identify** - Find gaps or areas to improve
3. **Discuss** - Propose your contribution (optional but recommended)
4. **Create** - Develop your contribution
5. **Review** - Self-review against quality standards
6. **Submit** - Share via GitHub Discussions or Pull Request
7. **Iterate** - Respond to feedback
8. **Celebrate** - Your contribution is live!

### For Code:

1. **Fork** - Create your copy of the repository
2. **Branch** - Create feature branch
3. **Code** - Implement your contribution
4. **Test** - Verify it works
5. **Document** - Add comments and README updates
6. **Commit** - Clear, descriptive commit messages
7. **Push** - Upload to your fork
8. **Pull Request** - Submit for review
9. **Revise** - Address review feedback
10. **Merge** - Contribution accepted!

Detailed process: [CONTRIBUTING.md](../../../CONTRIBUTING.md)
